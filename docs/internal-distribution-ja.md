# 社内配布版の使い方

Windows 11 x64向けの社内評価用です。ZIPを展開して使います。.NET SDK、リポジトリ、Windows App Runtimeの別途導入は不要です。GitHub CLI (`gh`) と、利用するGitHubのアカウント・プロジェクトへの権限が必要です。端末の実行制限は社内の運用に従ってください。

## 導入と接続

1. 配布されたZIPを、書き込み可能な任意のフォルダーにすべて展開します。ZIP内から直接起動しないでください。
2. GitHub CLIが未導入なら、[公式配布元](https://cli.github.com/)から社内の手順で導入します。ターミナルで `gh --version` が表示されることを確認します。
3. `gh auth login --hostname github.com --web --scopes project` で利用するアカウントにサインインします。会社専用のホストを使う場合は `github.com` をそのホスト名に置き換えます。EMUも会社から指定されたアカウントとホストで認証します。すでにサインイン済みでプロジェクトの権限が足りない場合は `gh auth refresh --hostname github.com --scopes project` を使います。組織・リポジトリ・プロジェクト自体のアクセス権限も必要です。
4. `GhProjectsBoards.App.exe` を開き、**接続**でホストとGitHub CLIを指定します。アプリが権限不足を示したら、表示された内容を確認して認証をやり直します。トークンを資料や画面に貼り付ける必要はありません。
5. 対象のプロジェクトを開きます。評価では **第2027.04版**を使います。既存Issueを取り込んだ直後は **未発行 0 タスク**であることを確認します。

## 最初の計画と毎週の更新

最初に**設定**で見積工数・実績工数・見込み残存工数・日付の列と稼働日を確認します。タスク画面で見積工数、担当者、先行タスク、開始日を入力し、表とガントで日程を確認します。サマリーで工程別の状況と月別負荷、原因タスクを確認し、対象タスクに絞った計画で担当や開始日を調整します。担当者の判断は利用者が行います。

入力はPC内に保存されます。GitHubへ送るときは **発行**を開き、変更と競合を確認して **発行する**を選びます。結果が不明・未完了なら成功として扱わず、表示された対象を確認します。

毎週は、チームの更新後に **最新の情報に更新**を選び、基準日を合わせ、実績工数と見込み残存工数を確認します。新しい要求事項や遅延を計画に反映し、担当者の負荷を調整して発行します。未入力や計算できない工数はゼロとして扱いません。

## 更新・保存先・削除

更新時はアプリを閉じ、新しいZIPを別フォルダーに展開して起動します。古いファイルへの上書きやアプリ起動中の差替えは避けてください。保存先は通常 `%LOCALAPPDATA%\GhProjectsBoards\Registrations\PlanningEditor\v1` です。配布フォルダーを移動しても、このPCの計画は残ります。保存エラーが出た場合は再試行し、エラーを残したまま強制終了しないでください。

配布フォルダーを削除しても計画とGitHub CLIの認証は削除されません。PCを替える場合はGitHubへの発行を確認し、**設定**のエクスポートを使います。未発行の計画はそのPCに残るため、発行前にPCや保存先を廃棄しないでください。旧版への戻しは保存形式が一致する場合だけ行い、不明な場合は保存先を保全して配布担当者に確認してください。

## 同梱情報と評価

AI アシスト用に GitHub Copilot SDK 1.0.22 と Copilot CLI 1.0.98 のランタイムを同梱しています。`runtimes/win-x64/native` を含めてフォルダー全体を保持してください。CLI は別プロセスとして動作します。同梱の `copilot_runtime.dll` は SDK が生成する同一ランタイムの別名で、本アプリでは直接読み込みません。GitHub Copilot CLI License と SDK・関連ライブラリの MIT 表示は `notices` にあります。

操作の詳しい説明は、同梱の `マニュアル.md` をアプリの **ヘルプ** または **F1** で開いて確認できます。この導入ガイドは `使い方.md` として同梱されています。取り込み用の CSV テンプレートは同梱せず、アプリの **取り込み用 CSV を書き出す…** でプロジェクトの列設定から作成します。

`notices` に依存ソフトウェアの利用条件・著作権表示、`distribution-manifest.json` に配布物の識別情報があります。これらを保持してください。本アプリの配布物はMicrosoft製品の承認を示すものではありません。

このパッケージの作成・検査だけでは、クリーンPCや会社環境での動作確認は完了しません。社内評価では、開発者以外の利用者がこの資料だけで導入し、接続、1件の編集・発行、物理キーボードでの日本語入力、1営業日の利用と再起動後の入力保持を確認します。
