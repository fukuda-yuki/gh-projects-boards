# Project の計画と設定

## 評価用データで起動

PowerShell 7で `C:\w\g76\scripts\Start-Evaluation.ps1 -NoBuild` を実行します。Release未ビルドなら `-NoBuild` を外します。初回の依存関係復元は開発環境で済ませてください。MSB3030が出る長いパスでは、短いパスに移ってビルドします。

表示されたデータルートを控え、**接続** → **開発計画**を選びます。ghのパスは入力済みです。実アカウントやネットワークは使わず、1,000タスク・20人、**未発行 0 タスク**から開始します。再開は `Start-Evaluation.ps1 -NoBuild -Resume -DataRoot <表示された絶対パス>` です。状況日は2026-10-05に固定しています。

担当者person-U1には同じ日に4人時の作業が2件あり、その日の許容4人時を超えます。Project全体の許容量には収まるため、日別の超過と全体予測を比較できます。

## 起動と接続

[README の Build and run](../README.md#build-and-run)で Release をビルドし、必要なら GHPB_DATA_ROOT に評価用の絶対パスを指定して起動します。

1. gh.exe と接続先を確認し、**接続**を押します。認証は gh の保存済みアカウントを使います。
2. 自分と所属組織の Project 一覧から開きたい Project を選びます。URL を使う場合は **URLで開く**を展開します。
3. タスクと対応する GitHub 列が表示されます。開いている Project 名は画面上部に表示されます。左の Project 一覧で切り替えます。

## シートとガント

セルを選び、文字入力または F2 で編集します。Enter で確定して下へ、Tab で右へ移動します。日本語の変換確定 Enter はセルを確定しません。次の Enter でセルを確定します。Escape は入力を取り消します。

Shift を押しながらクリック・矢印、またはドラッグで範囲を選びます。Ctrl+C / Ctrl+V でコピー・貼り付け、Ctrl+D で先頭の値を下へコピー、Delete でクリアします。選択セルの右下のハンドルも上下へコピーできます。Ctrl+Z / Ctrl+Y は操作単位で元に戻す・やり直すです。

末尾の空行に入力するか **行を挿入** でタスクを追加します。**インデント**／**アウトデント** で親子関係を変えます。親の工数と日程は子から集計されます。先行タスクには ID 列の番号を指定します。タイトルの絞り込みでも ID は変わりません。

初期表示では ID から先行タスクまでを表示します。**列**から開始日指定・日程固定・Status を追加できます。表とガントの境界をドラッグするか、境界にフォーカスして左右キーを押すと幅を変えられます。**状況日**で計画の基準日を選びます。ガントは **日／週／月** を切り替えられ、横スクロールは表と独立しています。ガントのバーはドラッグ編集しません。計算値は斜体、未発行セルは印で区別します。選択行の開始理由と警告を確認して編集を続けられます。**担当者**で期間ごとの負荷を確認できます。

## CSVからタスクを追加する

1. [テンプレート](../templates/new-tasks.csv)をExcelなどで開き、1行に1タスクを記入します。アプリの出力先にも `templates/new-tasks.csv` があります。
2. シートの **CSVから追加**（幅が狭いときはツールバーの **…** 内）でファイルを選びます。UTF-8（BOMの有無を問わない）とShift-JISに対応します。
3. エラーがあれば表示された行を修正し、**CSVを選び直す**を押します。エラーが残る間は1件も追加されません。
4. 未発行のタスクと計算された日程を確認します。**元に戻す**で一括追加全体を取り消せます。GitHubに反映するには **発行**を使います。

| 列 | 入力 |
| --- | --- |
| キー | ファイル内で重複しない識別名。例 `design`。GitHubには送信しません。 |
| タイトル | 必須のタスク名。 |
| 見積 | 人時。例 `8`、`1.5`。空欄は未入力、`0`はマイルストーン。列自体は必須です。 |
| 担当者 | GitHubのログイン名。複数なら `;` 区切り。空欄は未割当。 |
| 先行タスク | キー、既存Issueの `#123`、または `owner/repository#123`。複数なら `;` 区切り。 |
| 親 | 親のキーまたは既存Issueの参照を1つ。 |
| 開始日指定 | 任意。`2026-10-13` または `2026/10/13`。 |
| リポジトリ | 任意。`owner/repository`。空欄ならProject設定の既定値。 |

既存Issueは開いているProject内のものを指定します。シートのID列とIssue番号は別です。参照はファイル内のキーを優先するため、数値キーと区別するときは `#` を付けます。担当者なしのタスクはProjectカレンダーの稼働率100%で計算します。親の見積と日程は子タスクから集計します。

同じファイルを再び選ぶと重複追加の確認が出ます。判定はファイル全体のバイト列によるため、内容や文字コードを変えたファイルは別扱いです。上限は5 MiB・10,000タスクです。

Sandbox Project 3には評価用の24タスク（Issue #864–#887）が用意されています。そのまま開いて確認し、同じCSVを再取り込みしないでください。

## Project の設定

**設定**を開きます。入力を確定すると自動保存され、日程が再計算されます。テキスト入力は別のコントロールへ移ると確定します。**元に戻す**で一操作ずつ取り消せます。

- **GitHub列**：Estimate、Remaining、Actual、Start date、Target date、開始日指定、日程固定を名前と型で自動対応します。選択を変更した場合は **最新の情報に更新**で新しい列の値を取得します。対応が曖昧な列は未設定になります。
- **不足する日程列を追加**：Project に開始日指定と日程固定がなければ追加し、対応付けます。このボタンは GitHub を変更します。
- **カレンダー**：月–金の 09:00–13:00 / 14:00–18:00、内蔵の日本の祝日（2025–2027）を使います。祝日の一覧を展開できます。**祝日CSVを読み込む**では内閣府形式の UTF-8 または Shift-JIS の CSV を選択します。会社休日・個人休日はカレンダーで日付を選んで **追加**します。取り消す日は一覧で選択して **削除**します。同じ日の重複追加はありません。
- **担当者**：この Project の稼働率を設定します。初期値は 100% です。0% は指定できません。
- **Project開始日**：必要な場合に yyyy-MM-dd で指定します。
- **既定リポジトリ**：新規タスクの作成先を owner/repository で指定します。
- Draft と Pull request は計画対象外です。件数を設定ページの末尾で確認できます。

**設定を書き出す**で JSON を保存し、別の評価用データルートで同じ Project を開いて **設定を読み込む**と、同じ設定を使えます。

## 更新と再起動

**最新の情報に更新**は Project 全体を取得します。未発行の編集は Project ごとに保持されます。終了時には実行中の取得を中止して保存完了を待ち、次回接続後に選択していた Project を開きます。以前のデータ形式は読み込みません。

保存失敗時は画面の理由を確認し、保存先を直して **保存を再試行**します。保存できない間はウィンドウを閉じず、現在の作業を保持します。入力が不正な場合はその入力を直してください。通常の設定変更や **元に戻す**は GitHub に書き込みません。

評価用 sandbox は github.com の fukuda-yuki の Project 3 です。URL は https://github.com/users/fukuda-yuki/projects/3。実際の認証・権限や企業環境の確認は個別に行います。

## 更新と発行

**最新の情報に更新**で GitHub の変更を取り込みます。同じセルを両側で変更した場合は **競合** と表示されます。取得に失敗したときは計画を保持します。接続を確認して同じボタンで再試行します。

**発行**でタスク・列・変更前 → 変更後を確認し、競合は **ローカルを採用**または **GitHubを採用**で解決します。**発行する**を押すまで GitHub には書き込みません。レビューを閉じても発行は続き、上部に処理段階が表示されます。

失敗したタスクを選ぶと理由が表示されます。修正後に **発行**で残った変更を送ります。**未検証**は **最新の情報に更新**で結果を確認してください。中断後は再起動して同じ Project を開き、更新または発行で続けられます。元に戻す操作はローカルだけを変更し、GitHub を戻す場合も改めて発行します。

## 担当者の負荷と予測

**担当者**を開き、日・週・月を切り替えて負荷を比較します。許容量はこの Project 全体の人時です。予測は実績＋残、差分は許容量−予測です。実績が空欄のタスクは集計上0時間として予測します。残が空欄なら「残が未入力」と表示され、予測と差分は未入力になります。負荷の色と「超過」で過負荷を確認できます。負荷セルを選ぶと、その期間に寄与するタスクが表示されます。担当者名の展開でもタスクと未配分の理由を確認できます。展開したタスクの担当者はProjectの候補または「担当者なし」から選びます。複数担当者の選択はタスク表で行います。

許容量・稼働率と、展開したタスクの担当者・残・実績・日程固定を編集できます。入力確定は Enter または別のコントロールへの移動、取り消しは **元に戻す**です。負荷を減らすために日程や担当者を自動変更することはありません。担当者が複数のタスクは個人へ重複計上せず専用の行に表示します。日程固定タスクの残は固定期間内の稼働日に均等配分します。
