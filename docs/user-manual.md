# Project の計画と設定

## 起動と接続

[README の Build and run](../README.md#build-and-run)で Release をビルドし、必要なら GHPB_DATA_ROOT に評価用の絶対パスを指定して起動します。

1. gh.exe と接続先を確認し、**接続**を押します。認証は gh の保存済みアカウントを使います。
2. 自分と所属組織の Project 一覧から開きたい Project を選びます。URL を使う場合は **URLで開く**を展開します。
3. タスクと対応する GitHub 列が表示されます。開いている Project 名は画面上部に表示されます。左の Project 一覧で切り替えます。

この版のタスク一覧は読み取り専用です。シート編集、Gantt、発行画面、担当者ビューはまだ利用できません。

## Project の設定

**設定**を開きます。入力を確定すると自動保存され、日程が再計算されます。テキスト入力は別のコントロールへ移ると確定します。**元に戻す**で一操作ずつ取り消せます。

- **GitHub列**：Estimate、Remaining、Actual、Start date、Target date、開始日指定、日程固定を名前と型で自動対応します。選択を変更した場合は **最新の情報に更新**で新しい列の値を取得します。対応が曖昧な列は未設定になります。
- **不足する日程列を追加**：Project に開始日指定と日程固定がなければ追加し、対応付けます。このボタンは GitHub を変更します。
- **カレンダー**：月–金の 09:00–13:00 / 14:00–18:00、内蔵の日本の祝日（2025–2027）を使います。祝日の一覧を展開できます。**祝日CSVを読み込む**では内閣府形式の UTF-8 または Shift-JIS の CSV を選択します。会社休日・個人休日はカレンダーで日付を選んで **追加**します。取り消す日は一覧で選択して **削除**します。同じ日の重複追加はありません。
- **担当者**：この Project の稼働率を設定します。初期値は 100% です。0% は指定できません。
- **Project開始日**：必要な場合に yyyy-MM-dd で指定します。
- **既定リポジトリ**：新規タスクの作成先を owner/repository で指定します。
- Draft と Pull request は計画対象外です。件数を設定ページの末尾で確認できます。

**設定を書き出す**で JSON を保存し、別の評価用データルートで同じ Project を開いて **設定を読み込む**と、同じ設定を使えます。

## 更新と再起動

**最新の情報に更新**は Project 全体を取得します。未発行の編集は Project ごとに保持されます。終了時には実行中の取得を中止して保存完了を待ち、次回接続後に選択していた Project を開きます。以前のデータ形式は読み込みません。

保存失敗時は画面の理由を確認し、保存先を直して **保存を再試行**します。保存できない間はウィンドウを閉じず、現在の作業を保持します。入力が不正な場合はその入力を直してください。通常の設定変更や **元に戻す**は GitHub に書き込みません。

評価用 sandbox は github.com の fukuda-yuki の Project 3 です。URL は https://github.com/users/fukuda-yuki/projects/3。実際の認証・権限や企業環境の確認は個別に行います。
