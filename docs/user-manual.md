# Project の計画と設定

## 評価用データで起動

開発用リポジトリを現在のディレクトリにしたPowerShell 7で `./scripts/Start-Evaluation.ps1` を実行します。ビルド済みなら `-NoBuild` を付けると速く起動します。初回の依存関係復元は開発環境で済ませてください。MSB3030が出る長いパスでは、短いパスに移ってビルドします。

表示されたデータルートを控え、**接続** → **第2027.04版**を選びます。ghのパスは入力済みです。実アカウントやネットワークは使わず、40要求事項＋1,000タスク（計1,040 Issue）・20人、**未発行 0 タスク**から開始します。再開は `Start-Evaluation.ps1 -NoBuild -Resume -DataRoot <表示された絶対パス>` です。

第2027.04版は2026年10月13日から2027年4月30日までのウォーターフォール型の版で、状況日2027-01-13の途中経過から始まります。工程はSA → UI・SS → PS → PG → PT → IT → ST → OTの順で、IT・ST・OTは版全体で同じ日に始まります。詳細設計（PS）は一部の担当者で見積を超え、残を見直したため工程の目標日に遅れています。person-U7は共通部品の製造を兼ねて製造工程で負荷超過になり、R09 SS-003は残0のままIssueが開いています。一年の版は `-Version 2027.10`、別の状況日は `-StatusDate 2027-02-17` のように指定します。工程別の数値はデータルートの `evaluation.json` にあります。

## 起動と接続

配布ZIPは[社内配布版の使い方](internal-distribution-ja.md)に従って起動します。開発環境では[README の Build and run](../README.md#build-and-run)で Release をビルドし、必要なら GHPB_DATA_ROOT に評価用の絶対パスを指定して起動します。

1. gh.exe と接続先を確認し、**接続**を押します。認証は gh の保存済みアカウントを使います。
2. 接続中のアカウントと所属組織の Project 一覧から開きたい Project を選びます。URL を使う場合は **URLで開く**を展開します。
3. タスクと対応する GitHub 列が表示されます。開いている Project 名はタイトルバーに表示され、クリックすると登録済みの Project を切り替えられます。一覧のチェックは、現在開いている Project だけに付きます。**Project を開く…** と **接続…** もここにあります。設定はタイトルバーの歯車ボタンから開きます。

## シートとガント

日付は `10/14 (水)` の形で表示し、編集するときは `2026-10-14` の形で入力します。計算された日付は薄い文字、入力した日付は濃い文字です。ID の右の列は、完了・遅れ・日付指定・未発行の変更などを記号で示します。遅れの記号は2種類です。

- **塗りつぶしの⚠（期限超過）**：発行済みの終了日が状況日より前なのに未完了のタスク、または発行済みの開始日が状況日より前なのに未完了で実績が未入力または 0h のタスクです。状況日当日の予定は含めません。
- **輪郭だけの⚠（予定より遅れ）**：期限超過には該当しませんが、先行の遅れなどで計算された終了日が発行済みより後ろになったタスクです。

要求事項の行は、折りたたんでいても配下に期限超過があれば塗りつぶしの⚠、それ以外で要求事項または配下が予定より遅れていれば輪郭だけの⚠を示します。終了日を赤い文字にするのは、期限超過の記号が付き、その行の終了日も発行済みより後ろになった場合だけです。発行済みの日付は、最後の更新または発行で確認した GitHub の日付です。

ガントは実績を濃く、残りを薄く、要求事項を括弧形のバーで示します。終了日が発行済みより後ろになると、その翌日から計算された終了日までを赤い破線で示します。期限超過の記号が付く行だけ、この区間を薄い赤で塗り、日・週では「+N日」を添えます。予定より遅れだけの行は破線のみです。月・全期間では数値ラベルを省略し、ツールチップと選択行の説明で確認できます。N は Project カレンダーの稼働日数で、土日・祝日・会社休日を除きます。

入力した未発行の値は黄色の地と角の印で、再計算だけで変わった開始日・終了日は角の印だけで示します。要求事項の集計工数には未発行の印を付けません。

セルを選び、文字入力または F2 で編集します。Enter で確定して下へ、Tab で右へ移動します。日本語の変換確定 Enter はセルを確定しません。次の Enter でセルを確定します。Escape は入力を取り消します。

Shift を押しながらクリック・矢印、またはドラッグで範囲を選びます。Ctrl+C / Ctrl+V でコピー・貼り付け、Ctrl+D で先頭の値を下へコピー、Delete でクリアします。選択セルの右下のハンドルも上下へコピーできます。Ctrl+Z / Ctrl+Y は操作単位で元に戻す・やり直すです。

要求事項の親行から子タスクを折りたたみ・展開できます。親行のタイトルセルを選択した状態では Ctrl+← / Ctrl+→ でも操作できます。**すべて折りたたむ**で版全体を見渡し、**すべて展開**で詳細へ戻ります。タイトルで絞り込む間は、折りたたんだ子も一致すれば表示します。絞り込みを解除すると元の折りたたみ状態に戻り、選択行が隠れると表示されている親へ移ります。入力が不正なときや日本語変換中は、入力を直すか確定してから切り替えます。

先行タスクには ID 列の番号を指定します。**先行タスクを追加…**では要求事項・タスク名・Issue番号で検索して追加できます。既存の先行タスクは計画外のものも保持され、追加は **元に戻す**で一操作ずつ取り消せます。絞り込みや折りたたみで ID は変わりません。

末尾の空行に入力するか **行を挿入** でタスクを追加します。**インデント**／**アウトデント** で親子関係を変えます。親の工数と日程は子から集計されます。

初期表示では ID から先行までを表示します。ウィンドウ幅が 1,280実効ピクセル 以上なら、この10列が横スクロールなしで収まります。狭いウィンドウではガントを最低320実効ピクセル確保し、表を横スクロールします。コマンドバーの「…」にある **表示列**から開始日指定・日程固定・ステータスを追加できます。表とガントの境界をドラッグするか、境界にフォーカスして左右キーを押すと幅を変えられます。**状況日**で計画の基準日を選びます。ガントは **日／週／月／全期間** を切り替えられ、**全期間**は絞り込みや折りたたみで隠れたタスクを含む日程全体と状況日を表示します。左右に余白を確保し、ウィンドウや境界の幅を変えると再び全体を収めます。**選択タスクの日程へ移動**で選択行の開始日へ移動します。開始日がなく終了日だけなら終了日へ移動します。縦スクロールだけでは表示日付は変わりません。横スクロールは表と独立し、バーのドラッグ編集はありません。日・週・月へ尺度を切り替えると、選択行の開始日（開始日がなければ終了日、日付のある選択行がなければ状況日）が左から約4分の1の位置に来ます。日・週・月では、選択や編集だけでは表示日付を移動しません。**担当者**で期間ごとの負荷を確認できます。

表の直上の説明行には、選択したタスクの ID・名前、開始と終了の理由、遅れの表示、右端に Issue へのリンクが出ます。開始の理由には先行タスクの ID などを表示します。終了の理由は、着手済みなら「終了: 状況日 11/11 から残り 16h」、未着手なら「終了: 開始から 40h」、保持する指定日なら「終了: 指定」です。完了・要求事項・工数0のタスクなど、説明が当てはまらない場合は終了の理由を表示しません。

- 期限超過は赤い薄塗りのラベルで「完了予定 11/10 を過ぎて未完了」または「開始予定 11/9 を過ぎて未着手」と表示します。終了日も後ろへ動いていれば「· +2 日」のように添えます。
- 予定より遅れは赤い輪郭のラベルで「発行済み 12/1 から +2 日」と表示します。開始日も発行済みより後ろで、開始の理由が先行タスクの場合は「先行の遅れによる」と添えます。
- 要求事項では「配下: 期限超過 1 · 予定より遅れ 17」のように0でない件数を表示します。その行の終了日も後ろへ動いた場合は、記号の種類に対応した薄塗りまたは輪郭のラベルを添えます。

未選択時は「タスクを選ぶと、開始と終了の理由がここに出ます」と表示し、右側に Project 全体の期限超過・予定より遅れの0でないタスク件数を示します。要求事項を重複して数えません。

画面下部のステータスバーには要求事項とタスクの件数、0でない期限超過・予定より遅れのタスク件数が表示されます。「計画」のときだけ、右側に実績・残り・発行済みからの遅れ・非稼働日の凡例が出ます。件数は他の画面でも確認できます。

## CSVからタスクを追加する

1. [テンプレート](../templates/new-tasks.csv)をExcelなどで開き、1行に1タスクを記入します。アプリの出力先にも `templates/new-tasks.csv` があります。
2. シートのツールバーの **…** にある **CSV から追加…**でファイルを選びます。UTF-8（BOMの有無を問わない）とShift-JISに対応します。
3. エラーがあれば表示された行を修正し、**CSVを選び直す**を押します。エラーが残る間は1件も追加されません。
4. 未発行のタスクと計算された日程を確認します。**元に戻す**で一括追加全体を取り消せます。GitHubに反映するには **発行**を使います。

| 列 | 入力 |
| --- | --- |
| キー | ファイル内で重複しない識別名。例 `design`。GitHubには送信しません。 |
| タイトル | 必須のタスク名。 |
| 見積 | 人時。例 `8`、`1.5`。空欄は未入力、`0`はマイルストーン。列自体は必須です。 |
| 担当者 | GitHubのログイン名。複数なら `;` 区切り。空欄は未割当。 |
| 先行タスク | キー、既存Issueの `#123`、または `owner/repository#123`。複数なら `;` 区切り。 |
| 親 | 親のキーまたは既存Issueの参照を1つ。 |
| 開始日指定 | 任意。`2026-10-13` または `2026/10/13`。 |
| リポジトリ | 任意。`owner/repository`。空欄ならProject設定の既定値。 |

既存Issueは開いているProject内のものを指定します。シートのID列とIssue番号は別です。参照はファイル内のキーを優先するため、数値キーと区別するときは `#` を付けます。担当者なしのタスクはProjectカレンダーの稼働率100%で計算します。親の見積と日程は子タスクから集計します。

同じファイルを再び選ぶと重複追加の確認が出ます。判定はファイル全体のバイト列によるため、内容や文字コードを変えたファイルは別扱いです。上限は5 MiB・10,000タスクです。

Sandbox Project 3の24タスク（Issue #864–#887）はCSV新規追加の例です。同じCSVを再取り込みしないでください。版全体の評価は別の既存WBS、R01–R39の39要求事項＋975タスク（計1,014 Issue）を使います。[版全体の評価手順](../evaluation/README.md)に従い、CSV例と混同しないでください。

## Project の設定

**設定**を開きます。入力を確定すると自動保存され、日程が再計算されます。テキスト入力は別のコントロールへ移ると確定します。**元に戻す**で一操作ずつ取り消せます。

- **GitHub列**：Estimate、Remaining、Actual、Start date、Target date、開始日指定、日程固定を名前と型で自動対応します。選択を変更した場合は **最新の情報に更新**で新しい列の値を取得します。対応が曖昧な列は未設定になります。
- **不足する日程列を追加**：Project に開始日指定と日程固定がなければ追加し、対応付けます。このボタンは GitHub を変更します。
- **カレンダー**：月–金の 09:00–13:00 / 14:00–18:00、内蔵の日本の祝日（2025–2027）を使います。祝日の一覧を展開できます。**祝日CSVを読み込む**では内閣府形式の UTF-8 または Shift-JIS の CSV を選択します。会社休日はカレンダーで日付を選んで **追加**します。取り消す日は一覧で選択して **削除**します。同じ日の重複追加はありません。
- **担当者**：この Project の稼働率を設定します。初期値は 100% です。0% は指定できません。
- **Project開始日**：必要な場合に yyyy-MM-dd で指定します。
- **既定リポジトリ**：新規タスクの作成先を owner/repository で指定します。
- Draft と Pull request は計画対象外です。件数を設定ページの末尾で確認できます。

**設定を書き出す**で JSON を保存し、別の評価用データルートで同じ Project を開いて **設定を読み込む**と、同じ設定を使えます。

個人休日は設定しません。担当者ごとの設定は名前と稼働率を表示し、日程と稼働可能時間にはプロジェクト共通の稼働日を使います。個人休日を含む古い設定ファイルやローカルデータは読み込めません。移行機能はありません。更新前にローカルの変更を発行または破棄し、新しいデータ保存先でプロジェクトを開いてください。

## 更新と再起動

**最新の情報に更新**は Project 全体を取得します。未発行の編集は Project ごとに保持されます。終了時には実行中の取得を中止して保存完了を待ち、次回接続後に選択していた Project を開きます。以前のデータ形式は読み込みません。

保存失敗時は画面の理由を確認し、保存先を直して **保存を再試行**します。保存できない間はウィンドウを閉じず、現在の作業を保持します。入力が不正な場合はその入力を直してください。通常の設定変更や **元に戻す**は GitHub に書き込みません。

評価用 sandbox は github.com の fukuda-yuki の Project 3 です。URL は https://github.com/users/fukuda-yuki/projects/3。実際の認証・権限や企業環境の確認は個別に行います。

## 更新と発行

**最新の情報に更新**で GitHub の変更を取り込みます。同じセルを両側で変更した場合は **競合** になります。競合セルは赤い輪郭と角の印で示し、背景は塗りません。セルを選ぶと、表の直上の説明行に「競合: GitHub では …」と GitHub の値が出ます。取得に失敗したときも計画は保持されます。

**発行**でタスク・列・変更前 → 変更後を確認し、競合は **ローカルを採用**または **GitHubを採用**で解決します。**発行する**を押すまで GitHub には書き込みません。レビューを閉じても発行は続き、処理段階はワークスペースに表示されます。

更新・発行中は上部コマンド行の直下に細い進捗バーが出て、実行中のボタンは **更新中…**／**発行中…** になります。処理中の計画は読み取り専用ですが、スクロールやレビューを閉じる操作はできます。ローカルの編集や元に戻す操作では、この進捗バーは出ません。

更新・発行・保存に失敗すると、作業カード上部のエラー通知（InfoBar）に理由と再試行ボタンが出ます。更新の **再試行** は再取得し、発行の **再試行** はレビューを開き直します。再試行だけでは発行せず、改めて **発行する**で確認します。保存失敗は **保存を再試行**で回復します。保存が成功すると保存失敗の通知は消えます。

失敗したタスクを選ぶと理由が表示されます。修正後に **発行**で残った変更を送ります。**未検証**は **最新の情報に更新**で結果を確認してください。中断後は再起動して同じ Project を開き、更新または発行で続けられます。元に戻す操作はローカルだけを変更し、GitHub を戻す場合も改めて発行します。

## 担当者の負荷と予測

**担当者**を開き、日・週・月を切り替えて負荷を比較します。許容量はこの Project 全体の人時です。予測は実績＋残、差分は許容量−予測です。実績が空欄のタスクは集計上0時間として予測します。残が空欄なら「残が未入力」と表示され、予測と差分は未入力になります。負荷の色と「超過」で過負荷を確認できます。負荷セルを選ぶと、その期間に寄与するタスクが表示されます。担当者名の展開でもタスクと未配分の理由を確認できます。展開したタスクの担当者はProjectの候補または「担当者なし」から選びます。複数担当者の選択はタスク表で行います。

週・月の平均が100%以下でも、日ごとの超過があれば「日超過」と最大負荷を表示します。負荷セルを開いて超過日を選ぶと、その日の原因タスクに絞れます。「期間全体」で戻ります。担当を変更すると平均と日ごとの警告が一緒に再計算されます。未算定の仕事はゼロ扱いしません。

許容量・稼働率と、展開したタスクの担当者・残・実績・日程固定を編集できます。入力確定は Enter または別のコントロールへの移動、取り消しは **元に戻す**です。負荷を減らすために日程や担当者を自動変更することはありません。担当者が複数のタスクは個人へ重複計上せず専用の行に表示します。日程固定タスクの残は固定期間内の稼働日に均等配分します。
