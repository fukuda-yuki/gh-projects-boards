# プロジェクトの計画と設定

## 評価用データで起動

開発用リポジトリを現在のディレクトリにしたPowerShell 7で `./scripts/Start-Evaluation.ps1` を実行します。ビルド済みなら `-NoBuild` を付けると速く起動します。初回の依存関係復元は開発環境で済ませてください。MSB3030が出る長いパスでは、短いパスに移ってビルドします。

表示されたデータルートを控え、**接続** → **第2027.04版**を選びます。ghのパスは入力済みです。実アカウントやネットワークは使わず、40要求事項＋1,000タスク（計1,040 Issue）・20人、**未発行 0 タスク**から開始します。再開は `Start-Evaluation.ps1 -NoBuild -Resume -DataRoot <表示された絶対パス>` です。

第2027.04版は2026年10月13日から2027年4月30日までのウォーターフォール型の版で、基準日2027-01-13の途中経過から始まります。工程はSA → UI・SS → PS → PG → PT → IT → ST → OTの順で、IT・ST・OTは版全体で同じ日に始まります。詳細設計（PS）は一部の担当者で見積工数を超え、見込み残存工数を見直したため工程の目標日に遅れています。person-U7は共通部品の製造を兼ねて製造工程で負荷超過になり、R09 SS-003は見込み残存工数0のままIssueが開いています。一年の版は `-Version 2027.10`、別の基準日は `-StatusDate 2027-02-17` のように指定します。工程別の数値はデータルートの `evaluation.json` にあります。

## 起動と接続

配布ZIPは[社内配布版の使い方](internal-distribution-ja.md)に従って起動します。開発環境では[README の Build and run](../README.md#build-and-run)で Release をビルドし、必要なら GHPB_DATA_ROOT に評価用の絶対パスを指定して起動します。

1. gh.exe と接続先を確認し、**接続**を押します。認証は gh の保存済みアカウントを使います。
2. 接続中のアカウントと所属組織のプロジェクト一覧から開きたいプロジェクトを選びます。URL を使う場合は **URLで開く**を展開します。
3. タスクと対応する GitHub のフィールドが表示されます。開いているプロジェクト名はタイトルバーに表示され、クリックすると登録済みのプロジェクトを切り替えられます。一覧のチェックは、現在開いているプロジェクトだけに付きます。**プロジェクトを開く…** と **接続…** もここにあります。設定はタイトルバーの歯車ボタンから開きます。

## シートとガント

工程列はタスク名の直後にあります。選択肢の名前を入力・貼り付け・下へコピーできます。空欄にするには Delete を使います。未設定の工程列は編集できません。

要求事項（子タスクを持つ行）はタスク名だけ編集できます。工数と開始日・終了日は子タスクから集計されます。担当者・先行などは GitHub にある値だけを表示し、編集・発行の対象にはなりません。選択すると編集できない理由が表示されます。

日付は `10/14 (水)` の形で表示し、編集するときは `2026-10-14` の形で入力します。計算された日付は薄い文字、入力した日付は濃い文字です。ID の右の列は、完了・遅れ・日付指定・未発行の変更などを記号で示します。状態の記号は次のとおりです。色だけでなく形とツールチップでも確認できます。

| 見た目 | 意味 |
| --- | --- |
| エラーバッジ（×を含む記号） | 競合、発行失敗、または GitHub で未確認。ツールチップに理由と確認方法を表示します。 |
| 塗りつぶしの警告記号 | 期限超過。詳しい条件は下記のとおりです。 |
| 輪郭だけの警告三角形 | 予定より遅れ、見積超過、または「残 0・未完了」。ツールチップで該当する状態を確認します。 |
| チェックマーク（✓） | Issue が閉じられ、タスクが完了しています。 |
| 鉛筆の記号 | 開始日指定または日程固定があります。 |
| 丸い点（•） | 未発行の変更があります。 |
| 記号なし | 上記の状態に該当しません。 |

複数の状態が重なる場合、記号は表の上から順に優先されます。警告三角形では予定より遅れが工数の警告より優先されます。ツールチップと読み上げには該当する各状態を表示します。

遅れの記号には次の意味があります。

- **塗りつぶしの⚠（期限超過）**：発行済みの終了日が基準日より前なのに未完了のタスク、または発行済みの開始日が基準日より前なのに未完了で実績工数が未入力または 0h のタスクです。基準日当日の予定は含めません。
- **輪郭だけの⚠（予定より遅れ）**：期限超過には該当しませんが、先行の遅れなどで計算された終了日が発行済みより後ろになったタスクです。

要求事項の行は、折りたたんでいても配下に期限超過があれば塗りつぶしの⚠、それ以外で要求事項または配下が予定より遅れていれば輪郭だけの⚠を示します。終了日を赤い文字にするのは、子タスクを持たないタスクで期限超過の記号が付き、終了日も発行済みより後ろになった場合だけです。要求事項の工数と日付は集計値として薄い文字で表示します。発行済みの日付は、最後の更新または発行で確認した GitHub の日付です。

ガントは実績工数を濃く、残りを薄く、要求事項を括弧形のバーで示します。終了日が発行済みより後ろになると、その翌日から計算された終了日までを赤い破線で示します。期限超過の記号が付く行だけ、この区間を薄い赤で塗り、日・週では「+N日」を添えます。予定より遅れだけの行は破線のみです。月・全期間では数値ラベルを省略し、ツールチップと選択行の説明で確認できます。N はプロジェクトカレンダーの稼働日数で、土日・祝日・会社休日を除きます。

入力した未発行の値は黄色の地と角の印で、再計算だけで変わった開始日・終了日は角の印だけで示します。要求事項の集計工数には未発行の印を付けません。

セルを選び、文字入力または F2 で編集します。Enter で確定して下へ、Tab で右へ移動します。日本語の変換確定 Enter はセルを確定しません。次の Enter でセルを確定します。Escape は入力を取り消します。

Shift を押しながらクリック・矢印、またはドラッグで範囲を選びます。Ctrl+C / Ctrl+V でコピー・貼り付け、Ctrl+D で先頭の値を下へコピー、Delete でクリアします。選択セルの右下のハンドルも上下へコピーできます。Ctrl+Z / Ctrl+Y は操作単位で元に戻す・やり直すです。

要求事項の親行から子タスクを折りたたみ・展開できます。親行のタイトルセルを選択した状態では Ctrl+← / Ctrl+→ でも操作できます。**すべて折りたたむ**で版全体を見渡し、**すべて展開**で詳細へ戻ります。タイトルで絞り込む間は、折りたたんだ子も一致すれば表示します。絞り込みを解除すると元の折りたたみ状態に戻り、選択行が隠れると表示されている親へ移ります。入力が不正なときや日本語変換中は、入力を直すか確定してから切り替えます。

先行タスクには ID 列の番号を指定します。**先行タスクを追加…**では要求事項・タスク名・Issue番号で検索して追加できます。既存の先行タスクは計画外のものも保持され、追加は **元に戻す**で一操作ずつ取り消せます。絞り込みや折りたたみで ID は変わりません。

末尾の空行に入力するか **行を挿入** でタスクを追加します。**インデント**／**アウトデント** で親子関係を変えます。親の工数と日程は子から集計されます。

初期表示では ID から先行までを表示します。ウィンドウ幅が 1,280実効ピクセル 以上なら、工程を含むこの11列が横スクロールなしで収まります。狭いウィンドウではガントを最低320実効ピクセル確保し、表を横スクロールします。コマンドバーの「…」にある **表示列**から開始日指定・日程固定・ステータスを追加できます。表とガントの境界をドラッグするか、境界にフォーカスして左右キーを押すと幅を変えられます。**基準日**で計画の基準日を選びます。ガントは **日／週／月／全期間** を切り替えられ、**全期間**は絞り込みや折りたたみで隠れたタスクを含む日程全体と基準日を表示します。左右に余白を確保し、ウィンドウや境界の幅を変えると再び全体を収めます。**選択タスクの日程へ移動**で選択行の開始日へ移動します。開始日がなく終了日だけなら終了日へ移動します。縦スクロールだけでは表示日付は変わりません。横スクロールは表と独立し、バーのドラッグ編集はありません。**表示単位**を日・週・月に切り替えると、選択行の開始日（開始日がなければ終了日、日付のある選択行がなければ基準日）が左から約4分の1の位置に来ます。日・週・月では、選択や編集だけでは表示日付を移動しません。**サマリー**で工程と期間ごとの負荷を確認できます。

表の直上の説明行には、選択したタスクの ID・名前、開始と終了の理由、遅れの表示、右端に Issue へのリンクが出ます。開始の理由には先行タスクの ID などを表示します。終了の理由は、着手済みなら「終了: 基準日 11/11 から見込み残存工数 16h」、未着手なら「終了: 開始から 40h」、保持する指定日なら「終了: 指定」です。完了・要求事項・工数0のタスクなど、説明が当てはまらない場合は終了の理由を表示しません。

- 期限超過は赤い薄塗りのラベルで「完了予定 11/10 を過ぎて未完了」または「開始予定 11/9 を過ぎて未着手」と表示します。終了日も後ろへ動いていれば「· +2 日」のように添えます。
- 予定より遅れは赤い輪郭のラベルで「発行済み 12/1 から +2 日」と表示します。開始日も発行済みより後ろで、開始の理由が先行タスクの場合は「先行の遅れによる」と添えます。
- 要求事項では「配下: 期限超過 1 · 予定より遅れ 17」のように0でない件数を表示します。その行の終了日も後ろへ動いた場合は、記号の種類に対応した薄塗りまたは輪郭のラベルを添えます。

未選択時は「タスクを選択すると、開始日と終了日の根拠を表示します」と表示し、右側にプロジェクト全体の期限超過・予定より遅れの0でないタスク件数を示します。要求事項を重複して数えません。

画面下部のステータスバーには要求事項とタスクの件数、0でない期限超過・予定より遅れのタスク件数が表示されます。「計画」のときだけ、右側に実績工数・見込み残存工数・発行済みの終了日からの遅れ・非稼働日の凡例が出ます。件数は他の画面でも確認できます。

ガント上の横ホイール、または Shift を押しながらのホイール操作は、行位置を保って表示日付を左右に動かします。Shift とホイール下向きで後の日付、上向きで前の日付へ移動します。通常の縦ホイールは行を上下に動かし、表の横位置は変わりません。

## CSVからタスクを追加する

1. [テンプレート](../templates/new-tasks.csv)をExcelなどで開き、1行に1タスクを記入します。アプリの出力先にも `templates/new-tasks.csv` があります。
2. シートのツールバーの **…** にある **CSV から追加…**でファイルを選びます。UTF-8（BOMの有無を問わない）とShift-JISに対応します。
3. エラーがあれば表示された行を修正し、**CSVを選び直す**を押します。エラーが残る間は1件も追加されません。
4. 未発行のタスクと計算された日程を確認します。**元に戻す**で一括追加全体を取り消せます。GitHubに反映するには **発行**を使います。

| 列 | 入力 |
| --- | --- |
| キー | ファイル内で重複しない識別名。例 `design`。GitHubには送信しません。 |
| タイトル | 必須のタスク名。 |
| 見積 | h。例 `8`、`1.5`。空欄は未入力、`0`はマイルストーン。列自体は必須です。 |
| 担当者 | GitHubのログイン名。複数なら `;` 区切り。空欄は未割当。 |
| 先行タスク | キー、既存Issueの `#123`、または `owner/repository#123`。複数なら `;` 区切り。 |
| 親 | 親のキーまたは既存Issueの参照を1つ。 |
| 開始日指定 | 任意。`2026-10-13` または `2026/10/13`。 |
| リポジトリ | 任意。`owner/repository`。空欄ならプロジェクト設定の既定値。 |

既存Issueは開いているプロジェクト内のものを指定します。シートのID列とIssue番号は別です。参照はファイル内のキーを優先するため、数値キーと区別するときは `#` を付けます。担当者なしのタスクはプロジェクトカレンダーの稼働率100%で計算します。親の見積工数と日程は子タスクから集計します。

同じファイルを再び選ぶと重複追加の確認が出ます。判定はファイル全体のバイト列によるため、内容や文字コードを変えたファイルは別扱いです。上限は5 MiB・10,000タスクです。

Sandbox プロジェクト 3の24タスク（Issue #864–#887）はCSV新規追加の例です。同じCSVを再取り込みしないでください。版全体の評価は別の既存WBS、R01–R39の39要求事項＋975タスク（計1,014 Issue）を使います。[版全体の評価手順](../evaluation/README.md)に従い、CSV例と混同しないでください。

## プロジェクトの設定

**設定**を開きます。入力を確定すると自動保存され、日程が再計算されます。テキスト入力は別のコントロールへ移ると確定します。**元に戻す**で一操作ずつ取り消せます。

- **GitHub のフィールド**：各入力欄の見出しは見積工数、見込み残存工数、実績工数、開始日、終了日、開始日指定、日程固定、工程です。選択肢と選択済みのフィールド名は GitHub 上の名前をそのまま表示します。Estimate、Remaining、Actual、Start date、Target date、開始日指定、日程固定、工程を名前と型で自動対応します。選択を変更した場合は **最新の情報に更新**で新しい列の値を取得します。対応が曖昧な列は未設定になります。
- **「開始日指定」「日程固定」を GitHub に作成**：プロジェクトに開始日指定と日程固定がなければ追加し、対応付けます。このボタンは GitHub を変更します。
- **カレンダー**：月–金の 09:00–13:00 / 14:00–18:00、内蔵の日本の祝日（2025–2027）を使います。祝日の一覧を展開できます。**祝日CSVを読み込む**では内閣府形式の UTF-8 または Shift-JIS の CSV を選択します。会社休日はカレンダーで日付を選んで **追加**します。取り消す日は一覧で選択して **削除**します。同じ日の重複追加はありません。
- **担当者**：このプロジェクトの稼働率と上限工数 h を設定します。稼働率の初期値は 100% で、0% は指定できません。上限工数は空欄にできます。入力が不正な場合は、その担当者の欄に戻って理由を表示します。IMEの変換確定だけでは設定を確定しません。
- **期間**：任意の開始日・終了日を yyyy-MM-dd で指定します。終了日が開始日より前なら保存できません。終了日は日程計算を制限しません。
- **工程**：割り当てたフィールドの選択肢とタスク数を確認します。未設定なら「GitHub のフィールド」で既存の単一選択フィールドを割り当てます。工程のフィールドを自動作成することはありません。
- **新規 Issue の作成先**：新規タスクの作成先を owner/repository で指定します。
- 計画対象外の項目は「計画対象外: ドラフト n 件・プルリクエスト n 件・参照できない項目 n 件」と設定ページの末尾に表示します。

**設定を書き出す**で JSON を保存し、別の評価用データルートで同じプロジェクトを開いて **設定を読み込む**と、同じ設定を使えます。

個人休日は設定しません。担当者ごとの設定は名前と稼働率、任意の上限工数 h を表示し、日程と稼働可能時間にはプロジェクト共通の稼働日を使います。個人休日を含む古い設定ファイルやローカルデータは読み込めません。移行機能はありません。更新前にローカルの変更を発行または破棄し、新しいデータ保存先でプロジェクトを開いてください。

## 更新と再起動

**最新の情報に更新**はプロジェクト全体を取得します。未発行の編集はプロジェクトごとに保持されます。終了時には実行中の取得を中止して保存完了を待ち、次回接続後に選択していたプロジェクトを開きます。以前のデータ形式は読み込みません。

保存失敗時は画面の理由を確認し、保存先を直して **保存を再試行**します。保存できない間はウィンドウを閉じず、現在の作業を保持します。入力が不正な場合はその入力を直してください。通常の設定変更や **元に戻す**は GitHub に書き込みません。

評価用 sandbox は github.com の fukuda-yuki のプロジェクト 3 です。URL は https://github.com/users/fukuda-yuki/projects/3。実際の認証・権限や企業環境の確認は個別に行います。

## 未発行の変更をすべて元に戻す

**最新の情報に更新**の右の **▾** から **GitHub の状態に戻す…** を選びます。プロジェクト全体を読み直し、入力した変更、新しく追加した未発行のタスク、競合の選択をすべて破棄します。Issue ごとの破棄はありません。GitHub への書き込みや新規 Issue の作成は行いません。

確認画面で、破棄するタスク数と入力した変更・再計算された日程の内訳、新規タスク数を確認します。既定のボタンは **キャンセル** です。**GitHub の状態に戻す** を押すと取得を開始します。発行結果が未確認の間は使えません。取得に失敗した場合や採用前に **中止** した場合、計画は変わりません。

完了後は **未発行 0 タスク** となり、日程は GitHub の値をそのまま表示します。**基準日**は読み直した当日になります。稼働率、上限工数、休日、列、担当者、プロジェクトの開始日・終了日などのローカル設定は保持します。次に計画を編集すると全体を再計算し、発行の確認には **（GitHub の状態に戻したあとの再計算）** と表示します。

戻したあとでも **元に戻す** を1回押すと、破棄した編集と新規タスクが、最新の GitHub の値に対する未発行の変更として戻ります。**やり直し**で再度破棄できます。未発行が0でも、このコマンドで読み直して日程を GitHub の値に戻せます。

## 更新と発行

**最新の情報に更新**で GitHub の変更を取り込みます。同じセルを両側で変更した場合は **競合** になります。競合セルは赤い輪郭と角の印で示し、背景は塗りません。セルを選ぶと、表の直上の説明行に「競合: GitHub では …」と GitHub の値が出ます。取得に失敗したときも計画は保持されます。

**発行**でタスク・列・変更前 → 変更後を確認し、競合は **この PC の値にする**または **GitHub の値にする**で解決します。**発行する**を押すまで GitHub には書き込みません。発行を始めるとレビューが進捗パネルに切り替わり、処理が終わるまでレビューを閉じたり開き直したりする操作はできません。

プロジェクトを開くとき・更新中・発行中は、計画の上に進捗パネルが表示され、処理名と現在の工程、取得件数や書き込み件数（わかる場合）が表示されます。処理が終わるまで計画は操作できません。URL で開く場合も **プロジェクトを確認** の段階から進捗パネルの対象となり、中止すると元の画面に戻ります。確認中は入力や別の「開く」操作はできません。プロジェクトを選んで開くときは選んだ名前がすぐに表示され、短時間で開ける場合は進捗パネルを表示しません。開く操作と更新は、取得した内容の採用前まで **中止** で操作前の状態に戻れます。ただし、更新中に作成済みと確認できた Issue と行の対応は保存され、中止しても残ります。それ以外の計画・履歴は変わりません。**日程を計算** に進むと中止ボタンは表示されたまま無効になり、処理の完了を待ちます。発行には中止ボタンはありません。ウィンドウを閉じると発行は中断され、次に **発行** すると残りを再開します。ローカルの編集・元に戻す・設定の操作では、このパネルは出ません。

更新・発行・保存に失敗すると、作業カード上部のエラー通知（InfoBar）に理由と再試行ボタンが出ます。更新の **再試行** は再取得し、発行の **再試行** はレビューを開き直します。再試行だけでは発行せず、改めて **発行する**で確認します。保存失敗は **保存を再試行**で回復します。保存が成功すると保存失敗の通知は消えます。

発行に失敗したタスクを選択すると、失敗の理由を確認できます。修正後に **発行**で残った変更を送ります。**GitHub で未確認**は **最新の情報に更新**で結果を確認してください。中断後は再起動して同じプロジェクトを開き、更新または発行で続けられます。元に戻す操作はローカルだけを変更し、GitHub を戻す場合も改めて発行します。

## サマリーで工程と負荷を確認する

**サマリー**は読み取り専用です。基準日時点の残り稼働日、完了見込、終了日までに必要な稼働、進捗、要注意タスクを確認します。終了日がなければ **設定を開く** で期間を設定します。完了見込は先行関係と見込み残存工数から計算し、担当者の負荷は含みません。必要な稼働が100%を超える場合は「超過」と表示します。

工程別の集計と日程、担当者 × 工程を比較できます。セルの表示を見込み残存工数・見込工数・進捗・期限超過に切り替え、月別では負荷率、超過日数、最大日次負荷を確認します。工数未入力のタスクは除外件数を明記し、既知の値だけを集計します。進捗は実績÷見込、差異は見込−見積です。 割合は整数で表示し、100%を超える値は切り上げます。タスクのない工程セルや配分のない月は「–」です。

工程行やセルを選ぶと選択箇所が強調され、対象タスクの詳細と絞り込みボタンが見える位置へ移動します。詳細のIDは計画のIDと同じです。要注意の件数は、計画をその対象タスクに直接絞り込みます。**この N タスクで計画を絞り込む** で計画に移り、先頭の対象タスクを選択します。件数を確認して修正できます。タイトルの絞り込みを消すと全体に戻ります。稼働率と上限工数は設定の **担当者** で編集します。稼働可能は稼働率×残り稼働日×8hで、上限工数がある場合は上限工数−実績（最低0）を超えません。


詳細の状態欄は、期限超過・予定より遅れ・見積超過・残 0・未完了・完了など、当てはまる状態だけを表示します。通常の未完了タスクは空欄です。長い説明はツールチップで全文を確認できます。詳細はページと一緒に縦スクロールします。200件を超える場合は先頭200件と残り件数を表示し、**この N タスクで計画を絞り込む** で対象の全件を確認できます。

## 工数の用語と単位

| 意味 | 正式な名称 | 表の短い見出し |
| --- | --- | --- |
| 当初の見積もり | 見積工数 | 見積 h |
| これまでに使った工数 | 実績工数 | 実績 h |
| 現時点で見込む残りの工数 | 見込み残存工数 | 残 h |
| 実績工数＋見込み残存工数 | 見込工数 | 見込 h（該当する列がある場合） |
| 見込工数−見積工数 | 差異 | 差異 h（該当する列がある場合） |

単位は h です。表示値は「16h」、入力欄には「16」のように数値を入力します。表の短い見出し以外では正式な名称で案内します。

見積工数は当初の工数です。超過しても見積工数を変えず、見込み残存工数を見直します。見込み残存工数が空欄なら見積工数−実績工数（最低0）を薄い計算値として表示し、入力するまで空欄のまま保持します。この計算値は発行しません。見込工数は実績工数＋見込み残存工数、差異は見込工数−見積工数です。未完了で見込工数が見積工数を超えると状態欄に「見積超過」が表示されます。

着手済みタスクの見込み残存工数は、開始日と基準日の遅い方から担当者の稼働率で日程を計算します。正の見積工数または実績工数があるタスクで見込み残存工数が0でも完了にはならず、「残 0・未完了」と表示されます。先行タスクと基準日以降の長さ0の日程になります。工数0のマイルストーンは従来どおりです。

Issue を閉じると完了です。見込み残存工数は0、終了日はクローズした日（ローカル日付）になります。見込み残存工数0や開始日・終了日などの自動計算値は、対応する列を割り当てていない場合も表示しますが、未発行の変更や発行対象にはなりません。開始日がクローズ日より後なら、開始日もクローズ日に補正します。完了したタスクの見込み残存工数と終了日は編集・貼り付け・フィル・クリアできず、選択行に「完了したタスクは Issue のクローズで確定します（編集不可）」と表示します。見積工数・実績工数・タイトルなどは引き続き編集できます。GitHub の列と異なる値は角の未発行マーカーで示し、次の発行で反映します。再オープン後に最新の情報に更新すると、再び未完了として計算します。


見込み残存工数の計算値をそのまま入力値として採用するには、セルを編集状態にして Enter・Tab、または別のセルへ移動して確定します。同じ数値でも明示した見込み残存工数として保存され、その後に実績工数を変更しても維持されます。Escape は取り消し、セルを選択しただけでは変更しません。

## マイルストーンの期日と完了見込

GitHub のマイルストーンをガントの ◆ とサマリーで確認できます。期日より完了見込が遅ければ稼働日数の差を表示します。◆ を選ぶと、その期日を過ぎるタスクだけを計画に表示します。同じ期日に複数ある場合は、メニューで名前・完了見込・差を確認して対象を選びます。キーボードでも選択できます。遅れるタスクがなければ絞り込みは変わりません。全期間はマイルストーンの期日も含めます。サマリーのマイルストーンを選ぶと詳細に遅れるタスクが表示されます。

設定の「工程」でマイルストーンを対応させると、工程別の目標日と完了見込の差、工程の日程の ◆ を確認できます。「なし」なら目標日は表示しません。期日は GitHub で管理します。Issue の所属はシートのマイルストーン列で編集して発行できます。マイルストーンはタスクの日程を動かしません。同名のマイルストーンはリポジトリをまたいでまとめ、期日が異なる場合は最も遅い期日を使って注記します。

## 計画シートの列を設定する

シートの **表示列** から設定の **計画シートの列** を開きます。入力エラーがある場合は、セルを修正してから開きます。設定上部の **戻る** はスクロールしても表示されます。期間・工程の後にある表で、表示する列、表示名、GitHub の元フィールド、種類、計画シートで編集できるかを確認します。表示名を空欄にすると既定名に戻ります。ID とタスク名は常に表示します。ハンドルのドラッグまたは **上へ**・**下へ** の矢印ボタンで順序を変更し、見出し右側の **既定に戻す** で表示・順序・名前をまとめて戻します。各操作は **元に戻す** で取り消せます。列の設定はプロジェクトごとに保存され、設定の書き出し・読み込みにも含まれます。

追加したテキスト・数値・日付・単一選択、ラベル、マイルストーンはタスク行で編集して **発行** できます。単一選択とマイルストーンは既存名、ラベルはそのリポジトリの既存名をカンマで区切って入力します。未知の名前は登録されず、候補があれば候補を示すエラーになります。リポジトリにラベルやマイルストーンがない場合は GitHub で作成します。単一選択の候補がない場合は GitHub のプロジェクト設定で選択肢を追加します。リポジトリとイテレーション、要求事項行は読み取り専用です。列を非表示にしても値と未発行の編集は残ります。

表示していない列の値もプロジェクトの取得時に読み込みます。表示を切り替えるための再取得は不要です。見出しにマウスを置くと GitHub のフィールド名を確認できます。標準列に割り当てたフィールドは追加列には現れません。未発行の追加列編集があるフィールドを標準列へ割り当てるには、その編集を発行するか元に戻してください。
