The native-editor experiment defers constructing editors for columns that cannot be shown. Reveal/focus creates the original field's control synchronously; an existing editor is never rebound or replaced. It follows the bounded element-reduction direction in [Microsoft's collection-performance guidance](https://learn.microsoft.com/en-us/windows/apps/develop/performance/optimize-gridview-and-listview). This is a measured-cost correction, not a claim that all scroll pauses are explained or fixed. Cache size, saving, dispatcher priority, dependency versions and gh concurrency are unchanged.

Vertical-only scroll callbacks now synchronize the scrollbar without reapplying horizontal header/column state across all 1,000 row shells. Horizontal offset, viewport width or explicit column resizing still synchronize the header and visible rows; cached rows adopt the current offset/visibility when realized again. This removes measured repeated header work, without attributing every long pause to that work.
