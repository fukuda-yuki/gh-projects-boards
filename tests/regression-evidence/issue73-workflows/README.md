## Common causes and counterevidence

- A, purpose versus internal setup: supported for the first-planning handoff; contradicted by useful offline entry and direct ordinary effort input. Do not require all settings before unrelated work.
- B, different scopes/frequencies: repeated Actual input is already contextual and does not re-enter shared settings. Co-location alone does not justify splitting every dialog. Project-wide planning settings still lack explicit scope and purpose.
- C, disconnected successes: confirmed for invisible validation, stale operation errors and the incorrect offline cause. Counterexamples are safe Project switching, pending-input restart, explicit review and accurate unresolved Gantt states.
- Shared repair targets are command discoverability, context-preserving prerequisites, visible local correction and accurate message lifetime. Do not replace the domain, persistence or Apply boundaries to fix presentation.
