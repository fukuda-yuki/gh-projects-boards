# Native TableView investigation — Issue #202

## Scope and decision

This is a throwaway, never-merge Gate 1 experiment on `claude/202-tableview-prototype`, using the owner's 2026-10-14 Issue summary supplied in the task. No network, remote writes, app launch or desktop tests are authorized in this environment. The existing two project-file changes pin Windows App SDK `2.5.4-experimental`; they are input to the experiment, not a dependency upgrade performed here.

The PMO task is to refresh a Project, correct local planning inputs, and explicitly publish adopted changes. The experiment tests whether native editing can reduce maintenance while preserving that task. It does not change the product contract in `docs/spec.md` or adopt a renderer. DESIGN.md criteria particularly relevant here are selection versus editing, reachable invalid input, keyboard continuity, calculated-value presentation, and explicit local versus published state. Rendered appearance and human acceptance remain unverified.

Primary API evidence: `C:/w/sdk-logs/tableview-api-2.5.4-experimental.txt` (complete Tabular member-name dump supplied by the owner). Sample evidence: `C:/w/sdk-logs/gallery-tv/EditingCellsTable.txt`, `CustomColumnsTable.txt`, and `TableViewPage.xaml.cs:176-218` from Gallery v3.0.4. Member presence is evidence of availability, not evidence of native event order or performance. Inherited public TextBox/FrameworkElement events are usable; private members, template-part lookup and traversal of TableView internals are prohibited.

## Gate 1 probe and behavior list

Documentation precedes the new fixture and production changes. Expected physical IME behaviors are captured by a separate `PlanSheetTableViewImeTests` fixture (E2E/GridImeTableView), with the same opt-in rule and isolated fake-gh endpoint as `PlanSheetImeTests`; existing tests and Core are unchanged. The six scenarios are direct, f2, cancel, cancel-f2, reconvert, reconvert-f2. They must check exact physical text, no commit on IME confirmation, a single committed task on second Enter, next-row focus, cancellation, reconversion, saved state, no mutations and exit 0. Numeric rejection/retention also requires desktop verification. No behavioral Red or Green can be observed in this build-only session.

The opt-in is captured at application startup from `GHPB_PLAN_RENDERER=tableview`. The probe shares the sheet's visible row identities, pending input, errors, parsing, PlanSession and durable storage. It uses custom cell display/edit templates without two-way setters that could independently write a document. Native sorting is disabled. The table owns the Gate 1 body; the combined legacy sheet/Gantt body and its headers/scrollbars are hidden. Gantt alignment and hierarchy/range command UI are deliberately not presented as working features of this gate. The ordinary environment-unset renderer remains the control arm.

Editor IDs are `PlanCell{N}_Title` / `PlanCell{N}_Remaining`, assigned through public `AutomationProperties.SetAutomationId` on the owned TextBox. Display content has separate IDs, because a native cell need not create its editor until typing/F2. Tests activate the native grid cell then reacquire the editing TextBox; they must use the public UIA Grid cell and focus descendants after a commit, not assume an editor still exists. Do not retain a stale editor across native template replacement.

The non-F2 reconversion scenario uses native double-click to activate an editor for the already committed text. The initial direct-entry scenarios still use physical typing after a single cell click; no UIA value assignment or synthetic text substitution stands in for IME. These activation choices are hypotheses awaiting a desktop run. Failure to activate, preserve focus or navigate is a Gate 1 failure, not permission to weaken the assertions.

Implementation files:

- `src/GhProjectsBoards.App/PlanSheetTableView.cs`: TableView host, read-only bindable row projections, BeginningEdit/CellEditEnding bridge, native editor composition/cancellation, public automation IDs and anchored validation.
- `src/GhProjectsBoards.App/App.xaml`: TabularControlsResources after XamlControlsResources; public display/edit templates. Display bindings are explicit OneWay and the row projection has no value setters. The editor writes only to the existing Pending dictionary.
- `src/GhProjectsBoards.App/App.xaml.cs`: startup renderer choice.
- `src/GhProjectsBoards.App/PlanSheetView.cs`: opt-in host, refresh and pending/validation hooks. Existing Commit, Parse and PlanSession behavior is reused, not copied. The asynchronous save task is observed by the existing queue; native edit-ending is refused while that queue is busy. Native next-row navigation is intentionally left to TableView.
- `tests/GhProjectsBoards.E2E.Tests/PlanSheetTableViewImeTests.cs`: the six physical scenarios through the ordinary executable and isolated fake gh. The non-editing next-row assertion uses public Grid.GetItem and focus descendants; it does not require a TextBox to remain instantiated.

Public-API boundary: no TableView visual-tree traversal, named internal part, reflection, UIA invocation from product code, key replay or new operation/history store is used. The existing hidden ListView implementation is retained as the control arm. Gate 1 hides its combined sheet/Gantt body, header, divider, horizontal scrollbars and sheet-only command/filter/zoom row. The workspace's connection, unpublished count, refresh, publish, settings and normal-close paths stay available. The append-row identity is present but editing it is vetoed; task insertion is outside this gate. End is read-only and comes from the existing schedule, including held GitHub dates; its header does not claim every displayed date was recalculated.

Before advancing past Gate 1, execute these additional checks on the same three-row fake endpoint (the six-case IME fixture does **not** cover them):

1. Edit Remaining to `abc`, press Enter, then attempt focus loss and settings navigation. Require the numeric error anchored at that cell, retained `abc`, unchanged saved Remaining/unpublished count, and refused navigation with the editor reachable. Normal close must also refuse while invalid. Escape must restore the committed display, clear the error and add no operation.
2. Correct the retained text to a nonnegative number and commit. Require the existing PlanSession result and saved value, one local operation, and no mutation in calls.jsonl. Test unchanged F2/Enter and empty Remaining against the existing edit-baseline rules, including calculated defaults.
3. Attempt navigation/normal close during live composition; require refusal without losing composing text. Repeat after IME confirmation, and require only the explicit subsequent cell/flush boundary to commit. Verify read-only End never becomes an editor and a summary Remaining cannot be edited.
4. Inspect the default and opt-in ordinary screens, UIA IDs, error recovery, normal close, and retained pending input. Offscreen invalid-editor recovery cannot be claimed from the API dump; if it requires TableView internal parts, stop and record the failure. Do not implement Gate 2 to hide a Gate 1 recovery failure.
